# Issue: Pi reload 生命周期对齐

## Goal

让 grok-pi 的原生 Pager `/reload` 复用 Pi 官方 `ctx.reload()`，并把 Pi interactive reload 中可由 Pager 投影的生命周期结果完整同步回来，不新增第二个 TUI。

## 已确认差异

1. Pi interactive 在通过 streaming / compaction 门禁后先执行 `resetExtensionUI()`；Pager 原实现会保留已卸载 extension 的 status、widget、Remote TUI frame 与快捷键注册。
2. Pager 的 Pi theme `rediscover()` 声称会刷新已有 JSON，但实际重新扫描走了首次注册路径，已有主题会被跳过，编辑主题文件后 `/reload` 不生效。

## 验收标准

- [x] streaming 与 compaction 门禁继续由 Pi RPC 的真实状态决定。
- [x] 只有通过门禁的 reload 才清除 Pager 中可投影的旧 extension UI 状态；失败 reload 仍保持 Pi 的“先重置、后报错”语义。
- [x] reload 后已卸载资源不保留旧 widget/status/Remote TUI/shortcut；新 session-start 注册可正常重建它们。
- [x] 已编辑和已删除的 Pi theme JSON 在 reload 后反映到 Pager registry；当前 Pi theme 在仍可加载时重新应用。
- [x] command/model catalog 刷新与原生成功/失败 toast 不回退。
- [x] 为上述行为补充窄回归测试并运行相关 crate 测试、check 与 diff 审计。

## 实施阶段

### Phase 1 — 语义核对

- [x] 核对 Pi `InteractiveMode.handleReloadCommand()`、`resetExtensionUI()`、`AgentSession.reload()` 与 RPC 状态字段。
- [x] 核对 Grok-Pi `Action::PiReload → pi/session/reload → __pi_reload → ctx.reload()` 链路。

### Phase 2 — 实现

- [x] 在 Pi 门禁通过后发送窄的 Pager UI reset 通知。
- [x] 清理 Pager 映射的 extension UI 状态并恢复 session title。
- [x] 修复 Pi theme registry 重新发现的刷新/删除语义。
- [x] 为没有 Pi interactive editor 生命周期的 RPC 调用添加单次 reload 互斥，避免并发重载同一 Pi runtime。

### Phase 3 — 验证

- [x] 主题更新/删除单测已通过；extension surface 清理单测已添加并通过 `cargo check` 编译。

# Issue: Pi BTW 可持久化历史与原生 scrollback 查看

## Goal

在不修改 `pi-main`、oh-my-pi 或第三方 BTW 包源码的前提下，为 grok-pi 的原生 `/btw` 增加持久化、可恢复、可查看的历史。

## Contract

- 成功回答写入 Pi `appendEntry("pi-grok-btw/history/v1", data)`；custom entry 不进入 LLM context。
- `data` 使用 version 1，至少包含 `requestId`、`question`、`answer`、`createdAt` 和 `modelUsed`。
- adapter 从 Pi `get_entries` 的 active `leafId` 分支解析实体；不读取 sibling branch。
- session load/tree switch replay 通过 `pi/ui/btw_history` 投影到 Grok 原生 `BtwBlock`。
- 动态 Pi 命令 `/btw-history` 只刷新并查看实体，不发起模型调用；普通 `/history` 仍只表示 prompt history。

## Implementation

1. `extensions/pi-grok-btw/index.ts` fork/扩展 BTW bridge：完成后 append versioned custom entity，并注册 model-free history command。
2. `pi-grok-adapter` 解析 custom entity、缓存 active branch，并在 replay/command 后发出专用 UI notification。
3. Grok Pager 仅增加受控 ACP notification seam，复用既有 `BtwBlock`；当前 overlay、普通 prompt history 与持久化 BTW history 保持分离。

## Validation

- 静态源码审查：Pi `appendEntry`、`get_entries` active-branch replay、dynamic command、Pager BtwBlock projection 调用链已核对。
- `git diff --check` 已执行。
- 按用户约束未编译、未运行测试。

# Issue: 修复原生后台任务完成后未自动唤醒 Agent

## Goal

原生 grok-pi 后台任务完成后，完成事件必须可靠到达 Agent，并在允许自动唤醒的状态下启动后续 Agent turn。

## 背景/问题

本次 Python 测试使用的是宿主层 `functions.bash`，其完成结果只支持通过 `get_task_output` / `wait_tasks` 主动拉取，不属于本仓库的原生 task 总线。仓库内部已有 `TaskCompleted -> SessionCommand::Prompt` 自动唤醒链路，但需要补齐真实执行路径的回归覆盖，避免完成事件被配置或状态门禁静默吞掉。

证据链：

- `crates/codegen/xai-grok-tools/src/computer/local/terminal.rs:1593` 发送 `TaskCompleted`。
- `crates/codegen/xai-grok-shell/src/tools/notification_bridge.rs:382` 接收完成事件。
- `crates/codegen/xai-grok-shell/src/tools/notification_bridge.rs:397-566` 选择 synthetic Prompt 或 idle-gated fallback。
- `crates/codegen/xai-grok-shell/src/session/acp_session_impl/run_loop.rs:44-78` 执行 wake admission。
- `crates/codegen/xai-grok-shell/src/session/acp_session_impl/notification_drain.rs:339-407` 处理 fallback。

## Notes

最终根因在 `extensions/pi-grok-bash/index.ts:541-563`：成功完成分支把 `content` 设为空，并使用 `{ triggerTurn: false }`，所以 Pi 只记录自定义消息，不启动下一轮，Agent 也看不到完成结果。修复为：非显式 kill 的完成统一发送带输出/退出码的内容，并使用 `{ triggerTurn: true, deliverAs: "followUp" }`；显式 kill 保持不唤醒。

验证：`bun.Transpiler` TypeScript 转译通过；源级断言确认成功完成、失败完成和显式 kill 三条分支。仓库 Cargo 测试未作为本次验证项：改动只在 `extensions/`，且原生 shell lib-test 有既有测试编译错误、磁盘门禁曾阻塞构建。

# Issue: 移植模型管理中心与热更新

## 状态

- Status: Completed
- Owner: pi-grok
- Date: 2026-07-25

## Goal

在 `grok-pi` 中增加产品级原生模型管理中心，借鉴 `pi-session-manager` 的信息层级与交互语义，但不复制其 React/Tauri 实现。Grok Pager 继续作为唯一 TUI，Pi 继续拥有模型运行时；保存 `models.json` 后调用 Pi 官方 `ctx.reload()`，让运行中会话立即刷新模型目录，无需重启。

## Architecture Decisions

1. **UI 归 Pager**：新增原生 `Pi models` Modal，使用现有 `ModalWindow`、Theme、键盘/鼠标与响应式布局。
2. **模型归 Pi**：不修改 `pi-main`，不在 adapter 重实现 ModelRuntime；保存后复用现有 `Action::PiReload` → injected `__pi_reload` → `ctx.reload()`。
3. **配置事务归 Rust compatibility layer**：解析并保留未知 JSON 字段，严格校验已编辑边界；目录锁、外部修改冲突检测、原始字节备份、私有同目录临时文件原子替换。Windows 使用 `MoveFileExW(REPLACE_EXISTING | WRITE_THROUGH)`。
4. **不伪造 enabled 字段**：Pi `models.json` 没有 provider/model enabled 语义；模型切换继续走 typed ACP `session/set_model`，模型范围与认证仍归 Pi settings/CLI。
5. **PSM 仅作产品参考**：复用 Provider → Model → Detail 的三栏层级、草稿脏状态、危险操作二次确认、空状态、保存后读盘、备份恢复；不复制网络目录、HTTP 测试或 Tauri dispatch。
6. **Session 是激活状态真相源**：模型中心不乐观修改当前模型；切换成功后由现有 `handle_switch_model_complete` 更新 session，弹窗渲染时单向镜像已确认状态。

## Product Surface

- `/pi-models`，aliases: `/model-config`, `/models-config`。
- Command Palette 的 Model & Input 分组增加 “Manage Pi Models”。
- 三栏布局：Providers / Models / Details；窄终端降级为列表 + 详情。
- 键位：Tab/Shift+Tab 切栏，↑↓/jk 导航，`/` 搜索，`n` 新建，`c` 克隆，`e` 编辑，Space 切换布尔，`d` 删除（二次确认），`s` 保存并热更新，`r` 重新读盘，`u` 恢复最近备份，`a` 激活当前已加载模型，Esc 取消编辑/清搜索/关闭。
- 详情字段：Provider name/baseUrl/api/apiKey/authHeader/headers；Model id/name/api/reasoning/input/contextWindow/maxTokens/cost/thinkingLevelMap。
- 状态栏显示路径、脏状态、冲突/校验错误、备份、热更新和已确认的当前模型。

## Acceptance Criteria

- [x] 缺失 `models.json` 时可打开空中心并创建首个 provider/model。
- [x] 非法 root/providers/provider/models、空/重复 provider 或 model ID、非法数值/JSON 字段会在写盘前失败。
- [x] 保存时不会跟随 symlink；并发写通过目录锁串行化；磁盘在打开后被外部修改时拒绝覆盖。
- [x] 每次成功覆盖前保存原始字节备份；写入失败保持原文件；可在中心恢复最近备份。
- [x] 新增/编辑/删除/克隆保存后触发 Pi 官方 reload，成功后 live catalog 立即看到变化，无需重启。
- [x] 模型激活仍使用 typed ACP `session/set_model`，不绕过 Pi 校验；无认证 provider 按 Pi 语义不会进入可用目录。
- [x] UI 支持键盘与鼠标，宽/窄终端无越界；空态、搜索无结果、脏状态、确认和错误均可见。
- [x] 不引入 Ratatui/Crossterm 到 adapter；不新增第二套 TUI；不修改 Pi 源码。
- [x] 窄测试、adapter 测试、binary tests/check/build、标准 `./build.sh` 和端到端热更新均有明确结果；已知基础设施 blocker 单独记录。

## Risks / Rollback

- 现有工作树在任务开始前已有 tutorial 等未提交改动，且与本功能共享 `README`、Feature Matrix、`grok-pi.rs`、verifier/baseline 等路径。为避免把用户原有工作混入，不自动创建 Git commit。
- 配置保存前生成原始字节备份；中心内 `u` 可恢复最近备份，恢复后同样走 Pi reload。
- Pi reload 失败不会自动回滚或覆盖新配置；错误由现有 reload surface 报告，用户可刷新或恢复备份。
- 完整 models.dev 浏览与 HTTP 模型探测不属于本次边界，避免把外部网络与凭证测试逻辑带进 Pager。

## Notes

- Pi 官方 `ModelRuntime::reloadConfig()` 与 extension `ctx.reload()` 是热更新事实源。
- `get_available_models` 会按 Pi 认证状态过滤自定义 Provider；`apiKey`、`/login` 或 CLI 认证仍是模型进入 `/model` 的前提。
- PSM 当前 writer 是备份后直接 `fs::write`；本实现加强为未知字段保留、冲突拒绝、目录锁、私有备份与跨平台原子覆盖。
